# 安全开发更新：单设备绑定（2026-10-09）

- 60 秒临时流量引导现在同时匹配**指定测试设备 IPv4 和已解析的设备 MAC**，避免仅凭源 IP 就影响局域网内其他设备。只有主路由能从邻居表确认设备身份时才继续。
- 如果主路由未识别测试设备，LuCI 会提示用户先连接设备并打开网页。无需手工填 MAC。
- 依旧使用临时 nft 表和独立策略路由表，不修改 DHCP 默认网关。
- 此项是安全强化，**不是端到端代理功能的验收**。动态 IP、MAC 随机化、网络拓扑与硬件卸载可能影响测试。真实流量路径、断电回退、恢复接管、DNS/UDP/IPv6 还没有通过设备验证。
- 请保持生产全屋自动引流锁定，勿手工修改 `forwarding_verified`。

# 集中验收开发状态（2026-10-09）

本轮已提交：单设备策略引流的回程 SNAT 与包计数展示；服务启动时清理本插件的临时测试规则。现有 LuCI 初级向导仍保留，技术功能在高级设置。

**当前还不满足“一次完整验收”的交付条件：**
- 匹配包数不等于代理成功，需要通过客户端请求及实际出口证据验证。
- 尚未自动采集端到端测试结果，也未验证同网段回程、IPv6、DNS、UDP、ICMP redirect 与故障自动回切。
- 60 秒撤销是软件看门狗，不是硬件级绝对保证；路由器重启或服务崩溃仍有中断风险。
- 全屋自动保护继续锁定，不要手动设置验证标志绕过。

为避免对生产网络重复升级，此代码属于 **未验收开发版本**，请等待完整端到端验证版本后再进行单次安装测试。

## 单设备 60 秒引流验证（新增开发功能）

- 主路由安装位置：31.1；**测试默认关闭，必须在 Web 手动输入一台终端 IPv4**（例如此前使用的 Mac 31.131，但不预填）。
- 在旁路由实际开放仅供 LAN/主路由访问的 HTTP 或 SOCKS5 代理入口后，Web 填写代理检测地址并保存；点击“检测真实代理出口”确认通过。
- Web 保存测试设备 IP，点击“开始单设备测试”。守护测试只对指定 IPv4 源地址打标，使用独立 nft 表 `bypass_failover_test`、策略优先级 10200、路由表 202。和原全屋路由规则分开。
- 安装测试规则时预先写入过期时间，单独的看门狗进程每约 2 秒检查；60 秒后撤销。网页“立即撤销测试”和“强制直连”也会撤销测试规则。
- 测试需要路由器 `nft` 能匹配旁路由以太网 MAC；必须确认实际数据经过旁路由，浏览器打开正常本身不代表代理接管成功。
- **安全限制**：本实现尚未在你的真实网络完成回程与 Linux ICMP redirect 验证；60 秒看门狗进程被意外杀掉时，回退无法百分百保证。测试期间保持 SSH 管理连接和小米直连 Wi-Fi 备用设备，且先选择非关键终端。
- 该测试功能不等于“已完成全屋自动容灾”，不会自动将 `forwarding_verified` 设为 1；未完成回程实测前仍阻止全屋自动容灾。

# 旁路由智能容灾 v0.2.0-dev1

目标：安装于主路由 `192.168.31.1`，与旁路由 `192.168.31.2` 上的节点管理器完全独立。

## 本次代码更新

- LuCI 状态页增加**安全预检**、**真实代理出口检测**，原 Ping + DNS 检测保留为基础检查。
- 检测代理出口时必须明确配置 `proxy_endpoint`（如 `socks5h://192.168.31.2:端口`，需在旁路由上专门开启可供主路由访问的代理入口）；用 HTTPS `generate_204` 检测实际出口。**不应将匿名代理入口开放到 WAN**。
- 自动模式增加强制安全门槛：`forwarding_verified=1` 与真实代理测试均通过才允许开启。默认 `forwarding_verified=0`，因此 **默认禁止全屋引流**。
- 仍支持基础 HTTPS Webhook 发送与连续失败/恢复的防抖阈值，但不同通知商的消息格式尚未兼容验证。
- 提供 `build-ipk.sh`，以及 GitHub Actions 生成可下载的 `.ipk` 构建产物。GitHub Actions 运行与包安装结果未在路由器上确认。

## 当前不可称作完成的项目

1. **同网段实际引流：** 目前 fw4/nft 规则未通过 `192.168.31.1 → 192.168.31.2 → 192.168.31.1` 的真实转发、返回包、防 ICMP 重定向和 NAT 验证，不能保证可用。
2. **真实代理检测部署：** 代理检测器已编码，但默认没有可从主路由访问的受控代理端点，须按旁路由现有 PassWall 配置完成联调。
3. **IPv6：** 当前维持原有配置不修改，不是 IPv6 自动容灾。
4. **DNS：** 当前主路由 DNS 保持原配置，不是代理 DNS 自动切换；可避免安装时干扰联网，但尚无 DNS 故障切换实现。
5. **重启/进程崩溃自愈、通知格式及重复抑制、路由实机断电注入**均没有完成。
6. **零中断切换无法保证。** Wi-Fi 和客户端默认网关不需要变化，但连接可能断开或重建，部分国外网站直连不可访问。

## 安全部署

**不要将此版本自动模式用于全屋生产网络。** 不要为了跳过验证直接把 `forwarding_verified` 改成 1。

默认配置：`/etc/config/bypass_failover` 中 `mode=direct`，`forwarding_verified=0`。安装时不覆盖现有配置，不会开启路由策略。

页面：「服务 → 旁路由智能容灾」。

构建方式：在有 bash/python3/tar/ar 的 Linux 或 macOS 开发环境运行 `bash luci-app-bypass-failover/build-ipk.sh`；产物位于 `dist/`。构建不会验证设备实际转发链路。

当前阶段建议测试 Web 功能、安全预检、代理健康检测、通知；真实 IPv4 引流需测试环境或可恢复的维护时段验证后方可启用。
