# 旁路由智能容灾 v0.2.0-dev1

目标：安装于主路由 `192.168.31.1`，与旁路由 `192.168.31.2` 上的节点管理器完全独立。

## 本次代码更新

- LuCI 状态页增加**安全预检**、**真实代理出口检测**，原 Ping + DNS 检测保留为基础检查。
- 检测代理出口时必须明确配置 `proxy_endpoint`（如 `socks5h://192.168.31.2:端口`，需在旁路由上专门开启可供主路由访问的代理入口）；用 HTTPS `generate_204` 检测实际出口。**不应将匿名代理入口开放到 WAN**。
- 自动模式增加强制安全门槛：`forwarding_verified=1` 与真实代理测试均通过才允许开启。默认 `forwarding_verified=0`，因此 **默认禁止全屋引流**。
- 仍支持基础 HTTPS Webhook 发送与连续失败/恢复的防抖阈值，但不同通知商的消息格式尚未兼容验证。
- 提供 `build-ipk.sh`，以及 GitHub Actions 生成可下载的 `.ipk` 构建产物。GitHub Actions 运行与包安装结果未在路由器上确认。

## 当前不可称作完成的项目

1. **同网段实际引流：** 目前 fw4/nft 规则未通过 `192.168.31.1 → 192.168.31.2 → 192.168.31.1` 的真实转发、返回包、防 ICMP 重定向和 NAT 验证，不能保证可用。
2. **真实代理检测部署：** 代理检测器已编码，但默认没有可从主路由访问的受控代理端点，须按旁路由现有 PassWall 配置完成联调。
3. **IPv6：** 当前维持原有配置不修改，不是 IPv6 自动容灾。
4. **DNS：** 当前主路由 DNS 保持原配置，不是代理 DNS 自动切换；可避免安装时干扰联网，但尚无 DNS 故障切换实现。
5. **重启/进程崩溃自愈、通知格式及重复抑制、路由实机断电注入**均没有完成。
6. **零中断切换无法保证。** Wi-Fi 和客户端默认网关不需要变化，但连接可能断开或重建，部分国外网站直连不可访问。

## 安全部署

**不要将此版本自动模式用于全屋生产网络。** 不要为了跳过验证直接把 `forwarding_verified` 改成 1。

默认配置：`/etc/config/bypass_failover` 中 `mode=direct`，`forwarding_verified=0`。安装时不覆盖现有配置，不会开启路由策略。

页面：「服务 → 旁路由智能容灾」。

构建方式：在有 bash/python3/tar/ar 的 Linux 或 macOS 开发环境运行 `bash luci-app-bypass-failover/build-ipk.sh`；产物位于 `dist/`。构建不会验证设备实际转发链路。

当前阶段建议测试 Web 功能、安全预检、代理健康检测、通知；真实 IPv4 引流需测试环境或可恢复的维护时段验证后方可启用。
