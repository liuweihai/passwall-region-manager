# v1.3.0-rc1 集成验收说明

## 适用架构
主路由 OpenWrt 24.10: 192.168.31.1 (网关、DHCP、DNS)；同一 LAN 上 Nikki/Mihomo 旁路由 192.168.31.2。客户端无需更改默认网关或 DNS。

## 已实现的代码路径
- 主路由侧的 IPv4 TCP/UDP 流量经 fwmark / ip rule / 独立路由表指向旁路由；旁路由来源 MAC 被排除，避免二次引流环路。
- 仅把客户端发往主路由地址的 TCP/UDP 53 查询 DNAT 到旁路由；DNS 请求回程 SNAT 限定为 conntrack 已 DNAT 的连接，避免影响直接使用旁路由 DNS 的终端。
- NAT/DNS 与路由规则使用同一所有权/清理生命周期，健康检查失败达到阈值后整体撤销。
- 持续核对 nft prerouting/DNS 链、ip rule 和路由表；发现部分缺失时立即退回直连，等待重新健康检查再恢复。
- Web 界面通过实际规则存在性判定“已安装”，不再仅凭 mode/state 判定。

## 尚未被自动化构建证明的内容
- 同一 LAN 二次转发时，实际客户端请求及回包在特定硬件/交换芯片/fw4 规则下全程成功。
- 百度、Google、OpenAI 的浏览器真实访问体验及加载速度。
- QUIC、MTU/MSS、IPv6 在实际网络中的影响（此插件只管理 IPv4；没有承诺 IPv6 代理或容灾）。
- 真实旁路由断电、Nikki 崩溃、主路由重启和升级卸载的现场验收。
- 主路由直连回退后能否访问海外网站，取决于本身 WAN，插件无法保证。

## 一次性验收方案
1. 在主路由预先备份配置，覆盖升级并重启此插件服务。旁路由保持 Nikki Rule 模式，主路由 DHCP 仍下发 192.168.31.1。
2. mode=auto、state=bypass、live_routing=installed 和 dns_intercept_scope=client_queries_to_primary_only 仅代表规则已安装。用一台客户端直接体验百度、Google、OpenAI，并观察页面是否转圈。
3. 若正常，模拟一次旁路由不可用，观察自动回退到主路由直连，以及旁路由恢复后自动切回。切换时旧连接可能需要重建。
4. 若出现错误，一次性反馈客户端访问情况、插件状态和最新日志，不要求重复 60 秒或无关联诊断。

## 设计边界
此版本不是“主路由国内 IPv4 直连、国外 IPv4 经旁路由”的双表 GeoIP 架构，而是主路由将外部 IPv4 TCP/UDP 交给 Nikki，由 Nikki Rule 完成地区/域名分流。避免主路由与 Nikki 双层规则冲突。

自动化构建成功仅证明语法、约束检查和 IPK 打包；**不构成生产验收通过**。
