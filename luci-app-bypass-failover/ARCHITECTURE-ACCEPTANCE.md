# 单臂旁路由容灾：设计与验收计划

## 已确认的现场情况
- 主路由：OpenWrt 24.10，192.168.31.1，br-lan，DHCP 网关与 DNS 均为 .1。
- 旁路由：192.168.31.2，单臂同网段，默认网关回 .1，PassWall/Xray 运行中；本地 TCP REDIRECT 1041，SOCKS 1070 仅 127.0.0.1。
- Mac 192.168.31.131：主路由直连正常，原版 TCP 引流时百度也无法访问，撤销后恢复。
- 已排除主路由 LAN→LAN 默认禁止、旁路由 ip_forward=0、主路由 rp_filter 拦截等基础原因。
- beta4 标记 TCP HTTPS 探测不通过，但尚未区分出是打标、路由、远程目标或回程问题。

## 核心拓扑与风险
Mac → 主路由 .1 → 旁路由 .2（透明代理或国内直连）→ 主路由 .1 → WAN。
这是同网段单接口折返；需保证主路由不会对旁路由回来的包二次引流，且直连流量的 conntrack 和 NAT 不冲突。
主路由 SNAT 成 .1 不保证 PassWall 一定接管，也不保证国内直连的回程正确。
透明代理和远程可连的 SOCKS 不等价；不可要求用户暴露 1070 或安装 socat。

## 分阶段研发门槛
### 一、离线及只读验证
- 检查配置、策略优先级、路由表所有权、MAC 与接口；避免覆盖其他服务。
- FIB 断言：安装测试规则后，用 ip route get 的 mark/from/iif 参数确认下一跳确实指向旁路由；不符合立即撤销。
- 区分：基础存活、标记路径、客户端 TCP/回程、代理出口、故障回退；任何一个单项成功不等于全屋可用。
- 审核所有临时规则的创建、失败回滚、重启恢复与重复调用；CI 构建成功不等于设备连通。
### 二、解决真实转发路径
- 对照 PassWall 规则确认来自主路由 .1 的 TCP 流量是否会进入 REDIRECT。
- 针对中国 IP 直连经旁路由再次回主路由的情况，设计防环路和回程 NAT；需要同时考虑重定向连接。
- 若只改主路由无法可靠解决，须采用用户授权的一键旁路由配套配置，不能偷偷更改旁路由。
- 不能验证回程之前，禁止全屋自动切换。
### 三、最终一次受控实机验收
- LuCI 一键：预检 → 用户确认一次指定设备试验 → 采集 FIB/入口/SNAT/客户端 HTTPS/回程 → 自动撤销和结果报告。
- 分别验证国内外 TCP、DNS，以及旁路由故障/恢复；IPv4 TCP 以外流量明确说明范围。
- 验证失败保持 .1 直连。仅在真实回程及失败自动切换通过后才解锁自动模式。

## 非目标与安全边界
- 不修改现有 DHCP 网关 3,192.168.31.1 与 DNS 6,192.168.31.1。
- 不强制改 PassWall、不开放 1070、不安装 socat。
- 不把 IPK 构建成功标记为功能验收成功。
- beta4 及后续研发期间默认直连、自动保护保持锁定。
