# 单臂旁路由配套回程组件（实验性，未启用）

此目录不是安装到主路由上的正式功能。它提供一份单独放在 **旁路由** 的候选规则及独立回滚能力，用来验证先前导致 Mac 断网的回程 NAT 设计。

## 预期的数据路径

- 主路由 .1 收到 Mac .131 的 TCP，选路去旁路由 .2 时 **保留源 IP .131**，同时排除源 MAC 为旁路由的返回包。
- 旁路由 PassWall REDIRECT 捕获代理 TCP 时由本机 Xray 发起对外连接，不经过本组件的 SNAT。
- PassWall 对国内 IP 放行并需要从旁路由同一个 LAN 接口转发到 .1 时，本组件只对来源为测试设备 .131 的已转发 IPv4 TCP 执行 SNAT 为 .2。主路由看见 .2 发往 WAN 的流量，不会再送回旁路由；返回包由两端 conntrack 按各自 NAT 反向处理。

## 严格限制
1. 原主路由 beta4 的客户端引流功能已锁定。**仅安装旁路由组件不会实现代理或者容灾**。
2. 需明确设置 side、primary、client、lan，且显式 allow_apply=1 才允许 apply；没有开机自启动或自动修改 PassWall/DHCP。
3. audit 只读；apply 只创建 `inet bypass_failover_side` 独立表；remove 只删除该表。
4. 规则限定单个客户端、IPv4 TCP、LAN 出口及排除的本地和保留地址；UDP、DNS、IPv6 和其他客户端不在本组件控制范围。
5. nft nat 链计数仅在 **建立新连接** 时可用；不要把它当作全部转发包数或连通性证明。
6. 现阶段未测试同接口反向转发、PassWall ACL、fw4 转发策略、源地址保留模式及故障回退；也未排除规则间的优先级冲突。
7. 不要现在将此组件手动上传到现网旁路由执行。等主路由对应的保源地址引流及协同验证功能完成后，再做一次受控测试。

下一阶段：将两端配置由 LuCI 统一协同，增加可撤销的配置状态、独立的 WAN/DNS 检测、测试会话隔离、互相可观测的 conntrack 和超时失败自动回滚。在得到用户明确授权前不自动改动旁路由。
